# חיבור mishpacha-meals ל-Claude Code והעברת יומן האכילה

מדריך צעד-צעד ל-macOS. המטרה: לקחת את `food-tracker.html` הקיים והעובד, ולהתאים אותו כטאב בתוך mishpacha-meals — בלי לבנות מחדש.

---

## חלק א׳ — התקנת Claude Code (פעם אחת)

אם כבר מותקן אצלך, דלג לחלק ב׳.

1. פתח את **Terminal** (⌘+רווח, כתוב "Terminal", Enter).

2. הדבק את פקודת ההתקנה והרץ:
   ```
   curl -fsSL https://claude.ai/install.sh | bash
   ```
   זו ההתקנה ה-native המומלצת — לא צריך Node.js בשבילה, והיא מתעדכנת לבד.

3. סגור את חלון הטרמינל ופתח חדש (כדי שה-PATH יתעדכן), ואז ודא שההתקנה הצליחה:
   ```
   claude --version
   ```
   אמור להופיע מספר גרסה. אם מופיע "command not found", סגור ופתח טרמינל מחדש ונסה שוב.

4. הרץ בדיקת תקינות:
   ```
   claude doctor
   ```
   זה מוודא שההתקנה תקינה וש-`claude` מצביע למקום הנכון.

> **הערה על חשבון:** Claude Code דורש מנוי Claude בתשלום (Pro/Max/Team) או חשבון Console. המנוי החינמי לא כולל אותו. בהרצה הראשונה הוא יבקש להתחבר דרך הדפדפן — פשוט עקוב אחרי ההנחיה.

## חלק ב׳ — הבאת ה-repo למחשב

צריך שהקוד של mishpacha-meals יהיה על המחשב שלך מקומית. אם הוא כבר אצלך — דלג לשלב 3.

1. מצא את כתובת ה-repo ב-GitHub (כפתור ירוק "Code" → העתק את ה-HTTPS URL).

2. בטרמינל, לך למקום שבו אתה שומר פרויקטים (למשל `~/Projects`) ושכפל:
   ```
   cd ~/Projects
   git clone <כתובת-ה-repo-שהעתקת>
   cd mishpacha-meals
   ```
   (שם התיקייה עשוי להיות שונה מעט — התאם.)

3. ודא שאתה על הגרסה העדכנית:
   ```
   git pull
   git status
   ```
   `git status` אמור להראות "working tree clean". אם לא — יש שינויים לא שמורים, טפל בהם לפני שממשיכים.

לפני שמפעילים את Claude Code, שים את שלושת הקבצים שקיבלת ממני בתוך תיקיית הפרויקט (בשורש, זמנית — Claude Code יזיז אותם למקום הנכון):

## חלק ה׳ — הפעלת Claude Code ומתן המשימה

1. מתוך תיקיית הפרויקט, הפעל:
   ```
   claude
   ```
   הוא ייקח רגע לקרוא את מבנה ה-repo.

2. **תן לו את המשימה הזו כמו שהיא** (הדבק כבלוק אחד). היא מנוסחת בכוונה כך שיתבסס על הקוד הקיים ולא יבנה מחדש:

---

> יש בפרויקט קובץ `food-tracker.html` — אפליקציית יומן אכילה שכבר עובדת ובדוקה: לוגיקת בדיקת תוכנית תזונה, גרף משקל עם EWMA, תמיכה דו-לשונית עברית/אנגלית, בורר גופנים, והערכת ערכים תזונתיים ידנית ומתמונה.
>
> **אל תשכתב את הלוגיקה.** המשימה היא להתאים את הקוד הקיים למערכת הזו כטאב חדש, בשלושה שינויים ממוקדים בלבד:
>
> 1. **אחסון:** החלף את כל קריאות `window.storage` בקריאות ל-Supabase. הסכמה נמצאת ב-`02-supabase-schema.sql`. כל הנתונים מסוננים לפי `user_id` של המשתמש המחובר. השתמש בלקוח ה-Supabase ובמנגנון האימות שכבר קיימים בפרויקט — אל תיצור חדשים.
>
> 2. **קריאת ה-API:** היום הקוד קורא ישירות ל-`api.anthropic.com`. במקום זה, נתב את הקריאה ל-Supabase Edge Function שמחזיקה את מפתח ה-API בצד השרת. שלד הפונקציה נמצא ב-`03-edge-function-skeleton.ts`. ברירת המחדל של המודל צריכה להיות Haiku, עם אפשרות עתידית לשדרג ל-Sonnet.
>
> 3. **עטיפה כטאב:** שלב את ה-UI הקיים כטאב/route חדש בתוך המבנה הקיים של האפליקציה, לפי הקונבנציות של הראוטינג והרכיבים שכבר קיימים ב-repo. שמור על התמיכה ב-RTL.
>
> **לפני שאתה כותב קוד:** קרא קודם את מבנה הפרויקט והצג לי תוכנית קצרה — אילו קבצים תיצור, אילו תשנה, ואיך אתה ממפה את `window.storage` לסכמה. אני רוצה לאשר את התוכנית לפני שמתחילים. התקדם צעד-צעד ותעצור בצמתים, אל תבנה הכל בבת אחת.

---

3. Claude Code יציג לך תוכנית. **קרא אותה.** אם משהו לא ברור או נראה שהוא עומד לשכתב דברים קיימים — עצור אותו ותשאל. רק כשאתה מבין את התוכנית, אשר לו להמשיך.

## חלק ו׳ — הגדרת מפתח ה-API ב-Supabase (לא בקוד!)

זה קריטי: **מפתח ה-Claude API לעולם לא נכנס לקוד** ולא ל-repo. הוא יושב כ-secret ב-Supabase.

1. השג מפתח API מ-**console.anthropic.com** → API Keys → צור מפתח חדש. העתק אותו (מוצג פעם אחת).

2. טען קרדיט התחלתי לחשבון (המינימום בדרך כלל $5 — יחזיק אותך חודשים בשימוש אישי).

3. הגדר את המפתח כ-secret ב-Supabase. Claude Code יסביר לך בדיוק, אבל הפקודה בעקרון:
   ```
   supabase secrets set ANTHROPIC_API_KEY=<המפתח-שלך>
   ```
   (דורש את ה-Supabase CLI — אם אין, Claude Code ידריך בהתקנה.)

4. **הגדר התראת חיוב** ב-console.anthropic.com → Billing → Usage limits. קבע תקרה חודשית (למשל $5) כדי שלא יהיו הפתעות. גם אם משהו בקוד ישתבש ויקרא ל-API בלולאה, התקרה עוצרת את זה.

## חלק ז׳ — בדיקה, commit, ומיזוג

1. **בנייה מקומית — רף הקבלה שלך:**
   ```
   npm run build
   ```
   אם זה עובר — טוב. אם נכשל — אל תמזג. תן ל-Claude Code את הודעת השגיאה שיתקן.

2. הרץ מקומית ובדוק בפועל: רשום פריט ידני, נסה תמונה, בדוק שהמשקל נשמר, החלף שפה. ודא שהנתונים באמת נשמרים ב-Supabase (אפשר לראות בטבלאות דרך ה-Supabase Dashboard).

3. כשהכל עובד — commit ו-push:
   ```
   git add .
   git commit -m "Add personal food-log tab with Supabase storage and Edge Function nutrition estimates"
   git push -u origin feature/food-log
   ```

4. ב-GitHub, פתח **Pull Request** מ-`feature/food-log` ל-`main`. Vercel בדרך כלל בונה preview אוטומטי ל-PR — בדוק שה-preview עובד לפני שאתה ממזג.

5. רק כשה-preview תקין — מזג ל-main. Vercel יפרוס אוטומטית.
